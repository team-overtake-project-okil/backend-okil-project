# Імпорт наборів spike у векторну базу

## Що індексує цей імпорт

У docs/ai_context.md уже є пояснення восьми категорій Околу та правил
оцінювання. Цей імпорт додає фактичні записи окремих закладів і майданчиків
із відкритих наборів Львівської МТГ. Текст запису формується лише з полів
джерела: назви, типу, адреси та вибраних характеристик. Парсер не вигадує
описи послуг.

Для питання «що є в цьому гексі?» джерелом істини залишаються таблиці points
і stops та відповідний H3-запит. Векторний пошук підбирає текстові записи за
змістом і не обіцяє повного списку закладів міста. Для приватних клінік і
стоматологій у проєкті вже є окреме джерело OpenStreetMap у медичному POI
імпорті; цей набір міського порталу містить тільки комунальні медзаклади.

У перевірених знімках було 1 961 рядок. Парсер залишив 1 925 валідних:
13 записів харчування не мали назви, а 23 записи майданчиків мали неприйнятні
координати. Решта перевірених рядків мала потрібні назву/тип/адресу. Ці
кількості — знімок на дату дослідження; наступне отримання може мати інший
обсяг і нові помилки.

Не включені до цього індексу:

- перелік аптек і магазинів, файли якого оновлювалися у 2023 році;
- доступність зупинок із набору, останньо оновленого у травні 2025 року;
- укриття: це змінні дані для безпекових рішень, які треба отримувати через
  окремий перевірений структурований сервіс, а не з трьох найближчих
  семантичних збігів;
- річна статистика бібліотек: це показники за роками, а не записи POI;
- lviv.travel, карта «Доступне місто» й довідкові сторінки ЦНАП: для них у
  дослідженні #79 не було підтверджено формат експорту або права на повторне
  збереження тексту.

## Формат нормалізованого JSONL

Команда app.import_spike_data з параметрами --fetch і --snapshot отримує
сторінки CKAN Datastore у JSON і записує лише валідні записи у UTF-8 JSONL,
один запис на рядок. Приклад скороченого запису:

    {
      "category": "enjoyment",
      "content": "Комунальний заклад культури: ...\nКатегорія інфраструктури: дозвілля.\nАдреса з джерела: ...\nДані про облаштування доступності з джерела: ...",
      "metadata": {
        "document_id": "lviv-open-data.cultural_facilities",
        "chunk_id": "lviv.cultural_facilities.<стабільний-hash>",
        "source_kind": "city_open_data",
        "source_provider": "Lviv City Council Open Data Portal",
        "source_url": "https://opendata.city-adm.lviv.ua/dataset/...",
        "source_dataset_id": "...",
        "source_resource_id": "...",
        "source_record_id": "...",
        "source_license": "cc-by",
        "source_updated_at": "2026-01-14T...",
        "source_scope": "...",
        "entity_type": "...",
        "address": "...",
        "settlement": "Львів",
        "district": "..."
      }
    }

category, content і metadata відповідають колонкам ai_knowledge. Відображуваний
текст кодується наявною BGE-M3 інтеграцією Cloudflare у 1024 виміри. Для
записів майданчиків координати зберігаються лише після перевірки скінченності
та широкого діапазону Львівської МТГ; адреси без координат не геокодуються
навмання.

Не переносяться телефони, email, ПІБ керівників або контактні дані з рядків
джерел. Стабільний chunk_id формується з ідентифікатора джерела; коли він
повторюється, додається незмінний CKAN row ID, щоб відрізнити філії та зберегти
ключ при виправленні адреси чи назви. Якщо джерельного ID немає —
використовується SHA-256 нормалізованих назви, типу й адреси. Кожен ресурс є
окремим document_id, тому наявний імпортер може атомарно оновити саме його
рядки й не торкається документів інших джерел.

Звичайний `--apply` підходить для додавання або оновлення частини записів.
Для повного перевіреного знімка використовуй `--apply --replace-sources`.
Режим заміни оновлює записи та прибирає ті, яких більше немає у знімку.
Кожне джерело, присутнє у файлі, має бути представлене повністю. Джерела,
відсутні у файлі, та інші документи бази зберігаються. Якщо JSONL містить
невалідні рядки, заміна зупиняється до запису в БД.

## Повторювана процедура

З кореня бекенду в PowerShell:

    # 1. Завантажити джерела, перевірити рядки, зберегти snapshot та звіт.
    python -m app.import_spike_data --fetch all --validate-only --snapshot data/spike/lviv_open_data.jsonl --report outputs/spike-source-validation.json

    # 2. Перевірити збережений JSONL без API, embedding і БД.
    python -m app.import_spike_data --input data/spike/lviv_open_data.jsonl --validate-only --report outputs/spike-import-validation.json

    # 3. Створити embeddings як dry run. У БД нічого не записується.
    python -m app.import_spike_data --input data/spike/lviv_open_data.jsonl --report outputs/spike-import-dry-run.json

    # 4. Після перевірки цілі DB_URL застосувати до тестової гілки БД.
    python -m app.import_spike_data --input data/spike/lviv_open_data.jsonl --apply --report outputs/spike-import-applied.json

    # Для оновлення повного знімка з видаленням застарілих записів:
    python -m app.import_spike_data --input data/spike/lviv_open_data.jsonl --apply --replace-sources --report outputs/spike-import-replaced.json

    # 5. Read-only семантичний пошук; результат має source IDs, URL, ліцензію і дату.
    python -m app.search_ai_knowledge --query "Які культурні заклади мають пандус або інші засоби доступності?" --limit 5

Для --fetch потрібна мережа, але не потрібні Cloudflare, Groq чи доступ до БД.
Для dry run потрібні CLOUDFLARE_ACCOUNT_ID і CLOUDFLARE_API_TOKEN; для --apply
додатково потрібен DB_URL із прямим доступом до цільової БД. Спочатку
використовуй окрему тестову гілку БД. --apply дозволений тільки з нормалізованим
знімком --input, щоб перед записом можна було перевірити diff та повний звіт.

Повторний --apply використовує наявний транзакційний writer: зіставляє записи
за document_id + chunk_id, оновлює змінені записи й не додає повторно
незмінені. Embeddings усіх рядків готуються пакетами до першого запису в БД;
кожне джерело записується в окремій транзакції. Якщо один ресурс не пройшов
API/ліцензійну перевірку або сторінки Datastore неповні, його знімок не
створюється.

У режимі заміни поле `database_counts.deleted` показує кількість прибраних
рядків. Повторна заміна тим самим файлом має показати `inserted: 0`,
`updated: 0` і `deleted: 0`.

## Перевірка якості

Після імпорту перевір один запит із data/spike/lviv_open_data.jsonl і один з
іншими категоріями, наприклад:

- «Які культурні заклади мають у джерелі пандус?»
- «Де є дитячий майданчик з тренажерами?»
- «Які заклади харчування вказують години роботи?»

У результаті мають бути релевантний текст і metadata.source_record_id,
source_url, source_updated_at, source_scope. Перевіряй, що відповідь називає
час роботи як опубліковане джерелом значення, а не гарантовано поточний
графік; також не роби висновок, що повернуті кілька збігів є повним переліком
міста.
